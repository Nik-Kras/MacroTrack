# MacroTrack Follow-Up Audit - 2026-06-09

## Scope

Fresh audit pass after the required first-run onboarding change. Focus areas: onboarding/profile data integrity, PRD alignment, nutrition logging UX, local-first behavior, and database correctness.

## Findings

| ID | Severity | Area | Problem | Fix status |
|---|---:|---|---|---|
| B-01 | High | Onboarding data | `saveOnboardingProfile()` deletes every `body_record`, so a migrated user who re-runs setup can lose real measurement history. | Fixed |
| B-02 | High | Migration | Adding `profile.onboarded` defaults every existing database to `0`, forcing setup even when profile and body data already exist. | Fixed |
| B-03 | High | Profile progress | PRD requires progress bars per metric, but Profile only shows a weight progress bar and static current/desired text for other measurements. | Fixed |
| B-04 | Medium | Search | Food search still uses `%LIKE%` even though the app maintains an FTS table, making search weaker than the data model supports. | Fixed |
| B-05 | Medium | Product UX | Invalid custom-product inputs silently do nothing; users get no feedback about missing name/macros or invalid numbers. | Fixed |
| B-06 | Medium | Date validation | Onboarding accepts future birth dates and implausibly old ages, which can produce nonsensical macro targets. | Fixed |
| B-07 | Medium | Photo persistence | Local image copy errors are not caught in Dishes/Profile; a picker URI copy failure can throw instead of leaving the app usable. | Fixed |
| B-08 | Low | Profile editing | After onboarding, activity/goal/profile settings are visible but not editable without database reset. This is usable for first-run but weak for real users. | Deferred |

## Resolution Notes

- Onboarding now preserves existing body history and only removes the old synthetic one-row bootstrap measurement when detected.
- Databases with existing real logs or multiple body records are backfilled as onboarded during migration.
- Profile now renders per-metric progress bars for weight, waist, bicep, chest, both legs, and single leg.
- Food search now uses the SQLite FTS table for typed searches with safe prefix tokens.
- Custom-product validation now displays alerts for missing names and invalid nutrition values.
- Onboarding rejects invalid, future, and implausible birth dates.
- Dish/profile photo copy failures are caught and shown as alerts instead of throwing.
