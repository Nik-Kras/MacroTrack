# MacroTrack Code/UI Audit — 2026-06-09

## Scope

Audit pass over the Expo app implementation, local SQLite repository, core screens, and PRD alignment. Focus areas: bugs, weak UX, poor UI consistency, and local-first/data-model gaps.

## Findings

| ID | Severity | Area | Problem | Fix status |
|---|---:|---|---|---|
| A-01 | High | Database init | `getDatabase()` stores a failed initialization promise forever; a startup failure can leave the app unable to recover until process restart. | Fixed |
| A-02 | High | Dish macros | Custom dish logging uses source `food.kcal` via the dish view instead of the PRD-required 4/4/9 kcal calculation from macro grams. | Fixed |
| A-03 | High | Saved meals | The app can save a meal but has no way to list or log saved meals, so a PRD feature is effectively dead. | Fixed |
| A-04 | High | Nutrition UX | Selecting a food shows the grams editor below the full search list, often off-screen; the user can miss the actual “Add to diary” step. | Fixed |
| A-05 | High | Body records | Saving an empty Profile form calls SQLite and can violate `body_record` CHECK constraints, producing a runtime error. | Fixed |
| A-06 | Medium | Local photos | Picked dish/body photos store external picker URIs instead of copying into app-local storage, weakening the local-first photo contract. | Fixed |
| A-07 | Medium | Profile progress | Weight progress uses hard-coded `80 kg` as the start weight instead of the first recorded weight. | Fixed |
| A-08 | Medium | Statistics | Deficit/surplus multiplies targets by logged-day count, not selected span length, so week/month deficit can be understated when days are missing. | Fixed |
| A-09 | Medium | UI consistency | Nutrition and bottom tabs are dark, while Dishes/Profile/Stats remain light; the app feels like separate products. | Fixed |
| A-10 | Medium | App chrome | Status bar and loading text use dark colors on a dark background. | Fixed |
| A-11 | Medium | Custom foods | User-created products are not assigned curated category flags, so they do not appear in Protein/Carbs/Fats/Low kcal/High kcal filters. | Fixed |
| A-12 | Low | Search | Search uses basic `%LIKE%` matching despite having an FTS table. This is acceptable for v1 but weaker than the PRD’s “smart/fuzzy” wording. | Deferred |

## Resolution Notes

- Database initialization now clears the cached init promise on failure so the app can retry instead of remaining stuck.
- Dish and saved-meal logging now calculate kcal from macro grams using 4/4/9, keeping the diary consistent with the PRD.
- The diary now supports saved meal discovery and one-tap logging, with the quantity editor moved directly under the add tabs for food/dish selections.
- Empty body-record submissions are rejected in the UI and repository before hitting the SQLite CHECK constraint.
- Dish and progress photos are copied into app document storage through a shared local media helper.
- Profile progress now uses the first recorded weight as the baseline, and statistics use the selected calendar span for day/week/month deficit math.
- Dishes, Profile, Statistics, loading chrome, and charts now use the same dark, MyFitnessPal-inspired visual system as Nutrition.
- Custom user-created products now receive macro/category flags so they work in curated filters.
